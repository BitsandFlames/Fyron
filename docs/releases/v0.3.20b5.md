# Fyron v0.3.20b5

Released November 20, 2026 as **0.3.20 Beta 5**. Python 3.11 or newer is required. Current Fyron source remains available under **CC BY-NC 4.0**; third-party licenses and previously granted MIT permissions are unchanged.

## What changed

- **FHIR REST:** clearer execution/pagination reports, stricter cohort keys and response validation, controlled diagnostics and per-request protection of borrowed sessions.
- **PostgreSQL:** verified partition/combined exports, identifier-preserving CSV combination, actionable database errors and optional statement/lock timeouts.
- **DICOMweb:** exact study-folder labels without hashes, optional JSON sidecars, stricter retrieved-instance validation, request/worker deadlines, ordered task reports and staging cleanup after termination.
- **Documents:** optional MIME constraints, ordered task reports, bounded scheduling, cooperative cancellation and atomic result CSVs. Existing custom document IDs, flat output and optional completion records remain supported.
- **Shared workflows:** consistent colored or JSON diagnostics, protected upstream transport/parser messages, guarded redirects and configurable transient GET retries.
- **Documentation:** hands-on onboarding connects REST/SQL cohorts with downloads and pandas operations. Four dedicated parameter references cover every public client constructor/method argument, default and interaction.
- **Curate companion:** current source documentation now consistently describes [Curate](https://github.com/BitsandFlames/Curate) as a separate application. Fyron retains preview preparation; it has no bundled Curate launcher or app extra.

## Upgrade notes

DataFrame returns remain the default. DICOM and document batch methods accept `return_report=True` for `data` with `report.rows` and `report.summary`; task counts and returned series/file counts are separate.

Existing SQL CSV exports without matching completion records are no longer silently trusted. Review them and use explicit `overwrite=True` or `skip_existing=False` for intentional replacement. Disabling new completion JSON does not enable unverified skips.

Hash-free study labels require an explicit safe name unique to a study. Existing folders are not renamed or adopted automatically. Use both `save_study_manifest=False` and constructor `write_completion_record=False` to omit new DICOM JSON sidecars. Token caching is independent.

Borrowed HTTP sessions stay open and retain their headers, adapters and hooks. Fyron applies its own headers and redirect checks per request. Code that relied on a client constructor mutating a supplied session must configure that session explicitly instead.

The standalone Curate checkout is managed separately. Older Fyron distributions keep their historical scope; no earlier artifacts are replaced.

## Install

```bash
uv add "fyron==0.3.20b5"
```

The exact pin selects this prerelease. For manual installation use the wheel attached to the GitHub prerelease. PyPI availability depends on the separate package upload.

## Verification and limits

Tests use synthetic data, mocks and isolated loopback services. See the attached verification summary for this release's observed tests, installation probes and checksums. Passing checks do not establish clinical validity or compatibility with every institutional service.

Pagination exhaustion does not prove that a server has no hidden cap. DICOM validation accounts for received instances, not proof of a complete remote archive. SQL workers use separate transaction snapshots. Document cancellation waits for active network/authentication operations to reach their configured limits. Existing files and published outputs are preserved according to each method's explicit overwrite policy.
